RUN AND TEST DELPHI PROJECT HANDOFF 0.8.0.2
Last changed: 16 October 2026

BUILD AND START FROM SOURCE

1. Clone the public source repository or use GitHub's Code > Download ZIP,
   then extract the source to a writable local folder. Open
   DelphiProjectHandoff.dproj in RAD Studio 37 and build Win64 or Win32,
   Debug or Release. Install the supplied DAT design package first if you
   intend to edit its translation controls in the form designer.
2. Run bin\Win64\Release\DelphiProjectHandoff.exe if you built Win64 Release;
   otherwise use the matching bin\platform\configuration folder. Keep
   WebView2Loader.dll beside the executable and keep help, migrations,
   images and icons, and Localization in the source root.
3. DPH opens maximized. The logo and blue Delphi Project Handoff heading
   should appear above the six learner tabs, which share one row: Getting
   started, Handoff dossier,
   Learning library, Project map, Screenshots, and Application diagrams. The
   language selector should be visible beside the heading.

CHOOSE A LANGUAGE

Select a language in the header. DPH should change its labels and built-in
learning pages immediately and remember the choice when reopened. English is
the source language; the other 34 choices match VCL2FMXConverter v7. The
German also offers an experimental local translation of selected English
project prose in Handoff dossier and Learning library. DPH-authored memo
directions use the interface packs; some project-derived prose and technical
labels remain in their source language. Original files,
identifiers, and citations are unchanged. German preview captions can use
the selected project's Localization/Languages/de-DE.json when present;
otherwise the saved form captions remain. Other language
choices retain project content in its original language.

OPEN AN APPLICATION

4. Click Open application and select a Delphi .dproj, .dpr, or .groupproj file.
   Choose an application other than DPH itself. New captures remain temporary
   while you explore. When closing DPH or changing projects, choose Yes to save
   a .dphdb, No to discard the capture, or Cancel to keep it open. Save outside
   the selected application's source tree.
5. While DPH reads the project and its documents, inspect the progress bar.
   DPH reads the selected application without running it. Generated form
   previews are prepared when Screenshots is opened.
6. If the application was studied previously, click Open saved project and
   choose its .dphdb. Keep the adjacent .dphdb.views folder with the database.

CHECK THE LEARNING VIEWS

7. Open Handoff dossier. Check its capture status and purpose evidence, then
   inspect startup forms, command bindings, data candidates, and open
   questions. Follow a cited link to a screen or source object. Registration
   and static connections cannot prove what happens at runtime.
   If it says STALE capture, wait for automatic background verification when
   the original source is available, or reselect the source entry with Open
   application. Review again after preparation. PARTIAL capture means some
   syntax or semantic analysis is incomplete; inspect diagnostics and missing
   inputs. The capture time alone does not make a project stale. Static
   inspection only always remains because DPH does not run the target.
8. Open Learning library. Choose several topics on the left and check that
   paragraphs, headings, and lists are readable. The library draws from
   root-level documents and the selected project's top-level docs, Help,
   Guides, Manual, and Notes folders, including PDF, DOCX, Markdown, text,
   HTML, RTF, ODT, and useful log messages. It excludes JSON, XML, CSV,
   configuration files, unrelated parent folders, and nested release packages.
   If a project has separate upgrade or executable-update folders beside its
   own docs folder, verify their guides do not appear in the library.
   PDF, legacy Word, RTF and similar extraction requires LibreOffice at its
   standard Windows path. Check that an unreadable document gives a clear
   reason rather than an empty page. A readable non-Latin document should
   remain available in its original language.
9. Open Project map. Select a form, control, unit, routine, or variable to see
   its saved declaration and connections. Follow an action link if present.
10. Open Screenshots. DPH generates one empty-state PNG for each distinct form
    definition found in .fmx or .dfm. Select an image; it opens at Native
    pixels for readable detail. Scroll to inspect the rest, or choose Fit to
    see the complete screen. Form-derived
    images show saved controls and captions. They are not captures of the
    running target application, and custom painting or runtime data can differ.
11. Open Application diagrams. Choose a diagram type and read its purpose above
    the diagram.
    Form navigation shows possible screen connections; Execution and Caller /
    callee show routine connections; Data flow and Data lineage show possible
    information paths; Change impact shows dependencies. Select a shape to
    inspect the underlying project part. Large diagrams should scroll at a
    readable size instead of shrinking every label to fit the window. Use
    grouping or a selected object to focus a dense diagram. Diagrams reflect
    file evidence rather than a recorded run.

CHECK REOPENING AND SOURCE BUILD

12. Close DPH, restart it, and use Open saved project. Confirm that the same
    application, learning views, and generated screens reappear.
13. To modify the complete Delphi source, work in the extracted repository
    or source archive and rebuild in RAD Studio 37. Keep the source folder
    structure intact. Do not include personal .dphdb databases in a shared
    source archive.

If embedded HTML does not display, install the Microsoft WebView2 Runtime.
The project map and source-based analysis still require no target execution.
