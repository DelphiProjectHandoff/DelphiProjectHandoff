DPH DATABASE COLUMNS RUN AND TEST
Last changed: 12 October 2026
Requirement: 05.04 Columns, data types, and constraints

START AND FIND THE FEATURE
1. Save or discard any Knowledge draft and close the existing DPH window.
2. In File Explorer, paste this full path into the address bar and press Enter:
   C:\New Delphi Projects\Delphi Project Handoff\bin\Win32\Debug\DelphiProjectHandoff.exe
3. Click Attach project and choose the intended .dproj, .dpr or .groupproj, or
   Open cache and choose its .dphdb. Wait for the project to finish loading.
4. In the upper-right page selector, choose Database schema.
5. In the first selector on that page, choose column. In the evidence-state
   selector farther right, choose declared column. If it is outside the visible
   area, use the horizontal scrollbar under that command strip to move right.
6. Select a row. The labeled memo begins with Declared type, Nullability
   declaration and Default declaration. Scroll down for inline constraints,
   parent table declaration identity, source file/line, SHA256 and generation.
   Drag the divider below the list to resize the memo.
7. A column is a named table field. Its type describes its declared representation.
   Defaults are expressions captured from the script, and constraints state rules.
   Explicit NULL or NOT NULL means that clause occurs in the column entry.
   Not declared means absent from that entry; it does not establish effective
   nullability or an implicit default. Keys, domains, inheritance and later
   migrations may affect effective rules. DEFAULT NULL stays a default expression.
8. String default contents appear as [literal omitted]. Numeric, symbolic, simple
   function and parenthesized defaults retain captured text; nothing is evaluated.
   Original source/cache can contain sensitive data. Display omission does not
   scrub a backup or the original file.
9. Inline constraints show captured NOT NULL, NULL, PRIMARY KEY, UNIQUE,
   REFERENCES and CHECK text, with supported named clauses. For table-level
   constraints, select kind constraint and state captured constraint. Clear the
   text filter. These are captured clauses; key membership, referenced-column
   relationships, expression correctness and deployed enforcement are unverified.
10. Filter by table/column name, source file, declared type such as DECIMAL,
    explicit nullability or inline constraint text. Kind/state/text filters
    combine. Choose All in both selectors and clear text to reset. First page
    and Next page display up to 250 matches. Each duplicate table declaration
    retains its own columns; DPH never merges their definitions into a winner.
11. Choose kind gap and state unsupported to inspect extraction failures.
    Unsupported clauses, missing types/defaults, repeated defaults, conflicting
    NULL/NOT NULL and trailing empty entries retain sanitized source text and an
    explanation. Supported later entries can still be inspected. Empty results
    do not prove that the live table has no columns. Clear filters, check whether
    approved schema scripts were captured, and reassess when source is added.
12. Click Open source to read the original attached unchanged file. Detached,
    changed, historical or outside-project locations are refused in the memo.
    Attach the original project to its existing database, or Full reassessment
    after source changes, before using a captured source location.

SUPPORTED STATIC INSPECTION
Column/type/nullability/default/constraint facts come from supported CREATE TABLE
entries in captured referenced SQL resources. Entries split at outer commas.
Type identifiers, qualified types, supported multiword/time-zone/array/unsigned
suffixes and parenthesized parameters retain captured spelling. Default support
covers simple literals/numbers/symbols/functions and parenthesized expressions.
Complex unparenthesized expressions, generated columns, named DEFAULT constraints,
collation clauses and unsupported reference actions remain extraction gaps.
Type validity, expression semantics, inherited/domain rules and live enforcement
are not established. Table constraint text is retained without key relationships.
Existing resource/token/row bounds and source navigation guards still apply.
