DPH workspace operations - 11 October 2026

Run bin\Win32\Debug\DelphiProjectHandoff.exe from this project folder.
Use the page selector at the top right to reach any workspace page.
Select an application project with Open project; DPH rejects its own project.
Choose a new database filename in the offered Databases folder. Analysis reads
the selected application's source without building or running it.

Projects
Select Projects in the page selector. Select a saved database and click Open.
Remove removes only its catalog entry; it does not delete the database.
Opening saved results displays them before checking the available original
source. When original source is absent, the saved workspace stays detached.

Database tools
Preview retention before applying it. Recent count controls cached JSON views;
baseline, head, releases and review/image evidence remain protected. Immutable
database facts and authored revision history are not purged by this operation.
To protect a release, supply a release label and reviewer, then Keep release.
Integrity checks SQLite, foreign keys and referenced managed artifact hashes.
Backup asks for a NEW .dphdb filename. Keep that file together with the adjacent
.dphdb.views folder, including backup-manifest.json. Restore asks for the backup
database and a NEW destination database; it never replaces existing data.
These are explicit user operations; DPH does not schedule D: backups.

Rename review
Use this after reassessment identifies missing links in authored knowledge.
Enter a replacement name/file filter, click Find and select a proposal.
Inspect old/new declarations; the proposal is a candidate, not proven identity.
Enter the responsible reviewer and approve only the correct replacement.
Approval preserves text and old link history, adds the replacement link and
requires a separate knowledge-content review against the new source.

Search project
Enter words, choose all or a category, and click Search. Select a result to
read its excerpt and review state. Open result opens its object explanation
or authored record. Next 50 advances results; editing the query/category starts
a new search. Diagnostics show their message and source path in the excerpt.
Search covers captured object metadata, flow evidence, diagnostics and notes.
It does not search arbitrary neighboring files or execute query syntax.

Configurations, platforms and source encoding
Automatic reassessment reuses unchanged routine semantics where source bytes,
includes and bindings agree. A changed source file rebuilds its routines;
binding changes conservatively rebuild dependents. The status line reports
rebuilt/reused routine counts. Full reassessment bypasses routine reuse.
Attaching a project uses its declared configuration/platform defaults. The two
selectors then show choices discovered in its project metadata and conditions.
Select the required configuration/platform and click Full reassessment, or let
the next automatic check notice the changed selection. A raw DPR without this
metadata uses Debug/Win32 as explicit fallback selections.
The Source code page field is below the command buttons. Leave 0 for Unicode.
For legacy files enter the correct Windows code-page number, for example 1252
for Western Windows text. Click Full reassessment after changing it. Unicode
BOMs take precedence; decoding must round-trip the exact source bytes. DPH does
not guess a legacy encoding. Unsupported encodings leave diagnostic evidence.

Startup and shutdown
Choose Graphs in the top-right page selector, then click Whole program. It starts from the
program/library/package declaration and includes its entry body and reachable
unit initialization/finalization sections. In Explorer search for $entry,
$initialization or $finalization to inspect one phase. Select it and choose
Procedure CFG to see its statements. These are static source projections;
qualified phase links do not prove runtime ordering or successful completion.
Procedure CFG shows separate case labels/default sequences and explicit goto
targets where the label resolves within the same finally scope. Unknown or
cross-finally jumps are labeled unresolved_jump_target. With bodies run in
sequence, while ambiguous unqualified member bindings remain qualified.

Background work
In Explorer search for $async and select a result. Open its References and
Execution graph to follow the callback, start, wait or cancellation request.
A prepares_callback relationship means thread creation did not itself prove
a Start. A later known-handle Start has a separate qualified link. Queue and
Synchronize sites identify main-thread dispatch; Synchronize also shows its
normal-return wait contract. Captures appear in Data flow and References.
ASYNC_LIFETIME_REVIEW and ASYNC_WAIT_REVIEW diagnostics identify lifetime and
blocking questions. None of these links claims an observed execution order,
successful completion or safe lifetime. DPH does not run the selected app.

Resources and external definitions
Object references now include declared property read/write accessors. An indexed
property's result type is separate from its index parameters. Alias and inherited
member lookup link to captured declarations. A unique call candidate with unknown
argument types remains qualified, since a source parser cannot prove dispatch.
The Explorer kind selector includes resource and definition. JSON, XML and INI
entries have hierarchy and source evidence. RC lines and RES directories retain
explicit partial coverage for macros and opaque compiled payloads. JSON/XML
entry evidence points to the containing document, not a claimed exact token.
Supported literal file-loader references acquire only files inside the approved
project/dependency boundaries. Reference links show the consuming routine and
qualify loader spelling and lexical order. Dynamic paths and runtime override
precedence are not silently guessed.

Data and SQL
Select a variable in Explorer and open References or the Data flow graph.
derives_from links show inputs found in assignment expressions. They do not
prove the value reaching a later use. Select sql_statement in the Explorer
kind list to inspect static SQL sites. sql_table and sql_column narrow the list
to inferred schema references. Each reference keeps the containing source
range and hash; these are references from text, not a verified live schema.
Literal SQL.Text concatenation and directly loaded .sql files are supported.
SQL_DYNAMIC, SQL_SCHEMA_PARTIAL and SQL_EXPRESSION_PARTIAL explain unresolved
construction, unsupported statements and incomplete expression coverage.
DPH does not execute SQL or connect to the application's database.

Lifetime, exceptions and tests
Select a routine and open References. creates identifies a qualified creation
site; destroys identifies a possible cleanup action, not proof of completion.
raises and catches show source exception types and declared handler types.
An unresolved rethrow or dynamic type stays visible as a diagnostic. test_covers
links require a recognized explicit test attribute and a captured direct call.
They do not certify assertion quality or show a test result.

Dynamic controls
Choose dynamic_control in the Explorer kind selector. Select a $control object
and open References to inspect its constructor and assigned handle. Select the
containing routine to inspect mutates_property and candidate event assignments.
Form navigation includes these qualified relationships. A dynamic_control is
a source creation site, not a reconstructed runtime instance. Its count,
parent, geometry, visibility and lifetime require runtime or authored evidence.
DYNAMIC_CONTROL_REVIEW identifies these remaining questions.

Outputs
Choose output_artifact in the Explorer kind selector. Select a $output site
and read its signature for the writer and destination expression. References
links it to the producing routine and identifiable content parameter or source
collection. Data flow shows derives_from connections. A literal filename does
not verify the file format or prove the write succeeded. OUTPUT_PATH_DYNAMIC
means the destination still needs runtime or authored explanation.

Explorer hierarchy and evidence details
Clear the Explorer search and choose All in its kind list to see ownership
roots. Click an object once to inspect it. Select a [+] row and click Expand /
collapse selected, or double-click that row. [-] means the branch is open.
Next page pages through visible rows. Typing a search or selecting a kind shows
flat matching results; clear the filter to return to the expanded hierarchy.
Use the top-right page selector to choose Details. Select a statement, property
or relationship row. Read its text, certainty, rule, source range, hash and
generation in the right pane. Statements are sorted by source location, not
claimed runtime order. CFG entry/exit markers are labeled flow boundaries.
Properties are serialized overrides, not inferred framework defaults.
Click Open matching source for selected row to verify and open attached source
at its line. If source is detached or changed, cached evidence remains visible
and the old range is not applied to mismatched source bytes.

Form navigation
Choose Graphs in the top-right page selector and click All forms. The graph
starts from captured form resources and follows event bindings, matching fields,
declared instances and supported Show, ShowModal, Hide and Close actions.
Choose Form navigation in the graph type list for a graph focused on the current
object instead. All forms preserves the inspected object. A modal edge means a
source ShowModal action, not proof that a particular user reached that screen.
Factories, dynamic routing and actual visibility/order still require evidence.

Data-flow navigation
Select an input, output, field, property or routine, then choose Graphs and
Data flow. The graph includes incoming consumers and outgoing dependencies.
Click Project data for a broader captured projection. The inspector selection
is preserved. derives_from arrows point from a dependent value to its source
input or candidate function producer. Call-argument links identify a possible
formal binding; aliases, runtime values and calling context are not proven.
Graph commands scroll horizontally when the available toolbar width is small.

Grouped relationships
Choose Graphs, choose a graph type, then select Objects, Types or Units in the
grouping list. Procedure CFG retains statement-level nodes. Click a group to
open Details with its members and sampled relationship evidence. Select a
member and click Explain selected object to open its canonical explanation.
Counts describe the captured projection; a truncation warning means additional
objects were omitted. Arrow labels and certainty describe static evidence.

Form-design viewing
Choose Form designs in the top-right page selector. Thumbnail shows the captured
form gallery. Select a form and choose Fit, Native or Custom zoom. Drag the zoom
slider for 25-400 percent. Scroll to reach enlarged components. Click Full screen
for a focused borderless form view. Click Exit full screen, or press Escape, to
restore the surrounding panels. These are approximate source reconstructions.

Runtime screenshot evidence
Choose Screenshots. Enter the contributor name and capture date/environment in
the two fields, then click Import an existing PNG screenshot and select a file.
The selected Explorer object supplies the optional object link. Click an image
in the left thumbnail list. Choose Fit or Native pixels, or drag the zoom slider.
The bottom evidence pane shows attribution, generation, dimensions and hash.
Click Explain linked object to inspect its captured source context. Imported
images do not prove runtime origin or correctness without human review.

Coverage and reassessment
Choose Coverage in the top-right page selector. Each measure states what is
counted and its denominator. N/A means no eligible records. Select a diagnostic
in the lower list and click Inspect selected gap. Details shows its source
evidence; Open matching source checks the file hash before navigating.
Human review, pending tasks, tested-build evidence and documentation approval
remain separate from automatic analysis measures.
Reassessment of the same project retains surviving selections, bookmarks,
history, expanded branches, filters and the active page. If an object disappears,
DPH clears its stale inspector and reports the lost selection. Different project
identities reset navigation. Rename matching remains a separate reviewed action.

Versioned documentation sections
Choose Knowledge. Click New, enter a stable title, named author and body, and
choose the knowledge kind. In the lower two lists choose the destination document
and audience, or leave Automatic to derive them from the kind. Click Save.
The stable section ID and current revision appear below the lists. Selecting a
saved record shows its immutable revision history, including earlier document
and audience assignments. Verify review requires an explicit named reviewer;
saving alone does not verify content. Save or Discard edit before changing records.
Choose Publish. Select a full or selected-object bundle, optional file exclusions,
and the audience list beside Preview. all includes every guide; another audience
filters guide sections and attributed content. This audience filter is not a
privacy boundary: use file exclusions for source restrictions. Export writes a
new folder. Authored source generations remain distinct from publication identity.

Multiple documentation links
First select or create a section in Knowledge. Choose Knowledge links in the
top-right page selector. Choose entity, relationship, evidence, screenshot or
section in the first list. Enter an optional name filter and click Find targets.
Select a target in the left list, choose explains, cites, depends_on or illustrates,
then click Add link. Repeat for additional targets. The right list contains the
section's unsaved links. Select one and click Remove link to remove it.
Return to Knowledge and click Save. Reload the saved section, return to Knowledge
links, select a link and click Open saved target. Entity links open Explain;
relationship/evidence links open Details; screenshot links open the imported PNG;
section links show the exact pinned revision text. Older links cannot silently
gain approval against a newer generation. Review targets, save current links and
then use Verify review. Source navigation is disabled for historical evidence.
Offline exports include scoped links and revision anchors. Omitted target links
are explicitly counted when their source or audience is excluded.

Reviewing changed documentation
Choose Review tasks in the top-right page selector and click Refresh tasks.
Select a task in the list. BEFORE shows the comparison baseline and prior
authored revision; AFTER shows the current capture, original trigger and current
authored revision. Blank baseline fields mean no recorded comparison.
Choose an affected source object in the toolbar list and click Change impact
to inspect its possible dependents. Click Open knowledge to inspect or edit the
affected section and its links. Save changes before returning to task review.
Enter your reviewer name and click Verify selected only after inspecting the
evidence. DPH revalidates attached source and configuration, checks the exact
revision, and rejects obsolete rich-link targets. Click Retire selected when
the section is obsolete; its revisions remain preserved. A resolved task is not
proof that every operating procedure or undocumented requirement is complete.
Drag the divider between BEFORE and AFTER to resize the comparison panes.

Focused questions for the original author
Choose Author questions in the top-right page selector. Select a question to
read its prompt, evidence rule, source location/hash and captured generation.
Click Inspect evidence to open Details. Project-level procedure questions have
no precise source location. Lists are bounded to 100 questions, 20 per category.
Click Record author answer. DPH opens Knowledge with the prompt and an empty
Answer: field. Enter the named author and their actual response after Answer:,
then click Save. An empty response is rejected. Saving leaves human review pending.
Use named Verify review only after checking the response against current source
and its intended scope. A verified response without a pending task hides its
exact question. Changed evidence or renewed review can bring questions back.
DPH never supplies the author's business rationale or runtime results itself.

Learning the captured routine
Select a routine in Explorer. Choose Explain, then scroll to SOURCE WALKTHROUGH.
Read its captured expression and explanation. Under Possible next path, follow
the named true/false, iteration, return or exception destination to the stated
line in Source or the procedure CFG in Graphs. Source points are arranged by
source location; they are not a recorded execution. Repeated cleanup points
preserve distinct pending exits. Orange/possible_dynamic alternatives remain
uncertain. Long lessons state how many points or paths were omitted.
Use CHECK YOUR UNDERSTANDING to practice following an actual condition. Ask the
author to confirm intended outcomes; a static lesson cannot supply runtime results
or business rationale. The offline object page and document export use the same
lesson. This does not mark the selected program tested or the explanation reviewed.

Validation for this checkpoint
Run tools\validate-completion-wp1.cmd in an elevated command prompt from the
project folder with RAD Studio installed. Run tools\build-wp1.cmd for storage
migration/durability checks. A nonzero exit or FAIL indicates a failed check.
These automated checks do not substitute for first-time-user acceptance.
Run tools\build-learning.cmd --no-ui for deterministic explanation/publication
checks without native browser tests. Full build-learning.cmd additionally tests
worker recovery and native WebView rendering; that integration currently has an
unresolved access violation. Do not interpret --no-ui as a UI acceptance pass.
For discovery/resource checks run tools\build-wp2.cmd no-report. For semantic
checks run tools\build-wp3.cmd to compile, then run
bin\Win32\Debug\DPH.Tests.Semantics.exe with this project's full folder path as
its single argument. build-wp3.cmd alone compiles the tests; it does not run them.
