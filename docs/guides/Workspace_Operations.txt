DPH workspace operations - 11 October 2026

Run bin\Win32\Debug\DelphiProjectHandoff.exe from this project folder.
Use the page selector at the top right to reach any workspace page.
Select an application project with Open project; DPH rejects its own project.
Choose a new database filename in the offered Databases folder. Analysis reads
the selected application's source without building or running it.

Projects
Select Projects in the page selector. Select a saved database and click Open.
Remove removes only its catalog entry; it does not delete the database.
Opening saved results displays them before checking the available original
source. When original source is absent, the saved workspace stays detached.

Database tools
Preview retention before applying it. Recent count controls cached JSON views;
baseline, head, releases and review/image evidence remain protected. Immutable
database facts and authored revision history are not purged by this operation.
To protect a release, supply a release label and reviewer, then Keep release.
Integrity checks SQLite, foreign keys and referenced managed artifact hashes.
Backup asks for a NEW .dphdb filename. Keep that file together with the adjacent
.dphdb.views folder, including backup-manifest.json. Restore asks for the backup
database and a NEW destination database; it never replaces existing data.
These are explicit user operations; DPH does not schedule D: backups.

Rename review
Use this after reassessment identifies missing links in authored knowledge.
Enter a replacement name/file filter, click Find and select a proposal.
Inspect old/new declarations; the proposal is a candidate, not proven identity.
Enter the responsible reviewer and approve only the correct replacement.
Approval preserves text and old link history, adds the replacement link and
requires a separate knowledge-content review against the new source.

Search project
Enter words, choose all or a category, and click Search. Select a result to
read its excerpt and review state. Open result opens its object explanation
or authored record. Next 50 advances results; editing the query/category starts
a new search. Diagnostics show their message and source path in the excerpt.
Search covers captured object metadata, flow evidence, diagnostics and notes.
It does not search arbitrary neighboring files or execute query syntax.

Configurations, platforms and source encoding
Automatic reassessment reuses unchanged routine semantics where source bytes,
includes and bindings agree. A changed source file rebuilds its routines;
binding changes conservatively rebuild dependents. The status line reports
rebuilt/reused routine counts. Full reassessment bypasses routine reuse.
Attaching a project uses its declared configuration/platform defaults. The two
selectors then show choices discovered in its project metadata and conditions.
Select the required configuration/platform and click Full reassessment, or let
the next automatic check notice the changed selection. A raw DPR without this
metadata uses Debug/Win32 as explicit fallback selections.
The Source code page field is below the command buttons. Leave 0 for Unicode.
For legacy files enter the correct Windows code-page number, for example 1252
for Western Windows text. Click Full reassessment after changing it. Unicode
BOMs take precedence; decoding must round-trip the exact source bytes. DPH does
not guess a legacy encoding. Unsupported encodings leave diagnostic evidence.

Startup and shutdown
Choose Graphs in the top-right page selector, then click Whole program. It starts from the
program/library/package declaration and includes its entry body and reachable
unit initialization/finalization sections. In Explorer search for $entry,
$initialization or $finalization to inspect one phase. Select it and choose
Procedure CFG to see its statements. These are static source projections;
qualified phase links do not prove runtime ordering or successful completion.
Procedure CFG shows separate case labels/default sequences and explicit goto
targets where the label resolves within the same finally scope. Unknown or
cross-finally jumps are labeled unresolved_jump_target. With bodies run in
sequence, while ambiguous unqualified member bindings remain qualified.

Background work
In Explorer search for $async and select a result. Open its References and
Execution graph to follow the callback, start, wait or cancellation request.
A prepares_callback relationship means thread creation did not itself prove
a Start. A later known-handle Start has a separate qualified link. Queue and
Synchronize sites identify main-thread dispatch; Synchronize also shows its
normal-return wait contract. Captures appear in Data flow and References.
ASYNC_LIFETIME_REVIEW and ASYNC_WAIT_REVIEW diagnostics identify lifetime and
blocking questions. None of these links claims an observed execution order,
successful completion or safe lifetime. DPH does not run the selected app.

Resources and external definitions
Object references now include declared property read/write accessors. An indexed
property's result type is separate from its index parameters. Alias and inherited
member lookup link to captured declarations. A unique call candidate with unknown
argument types remains qualified, since a source parser cannot prove dispatch.
The Explorer kind selector includes resource and definition. JSON, XML and INI
entries have hierarchy and source evidence. RC lines and RES directories retain
explicit partial coverage for macros and opaque compiled payloads. JSON/XML
entry evidence points to the containing document, not a claimed exact token.
Supported literal file-loader references acquire only files inside the approved
project/dependency boundaries. Reference links show the consuming routine and
qualify loader spelling and lexical order. Dynamic paths and runtime override
precedence are not silently guessed.

Validation for this checkpoint
Run tools\validate-completion-wp1.cmd in an elevated command prompt from the
project folder with RAD Studio installed. Run tools\build-wp1.cmd for storage
migration/durability checks. A nonzero exit or FAIL indicates a failed check.
These automated checks do not substitute for first-time-user acceptance.
For discovery/resource checks run tools\build-wp2.cmd no-report. For semantic
checks run tools\build-wp3.cmd to compile, then run
bin\Win32\Debug\DPH.Tests.Semantics.exe with this project's full folder path as
its single argument. build-wp3.cmd alone compiles the tests; it does not run them.
