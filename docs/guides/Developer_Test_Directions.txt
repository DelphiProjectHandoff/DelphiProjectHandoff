DELPHI PROJECT HANDOFF 0.8.0.10 - DEVELOPER TEST DIRECTIONS
Last changed: 17 October 2026

Before opening the main form in the designer, install the supplied DAT design
package through RAD Studio's Component > Install Packages > Add command. See
export\DAT-component-kit\DelphiProjectHandoff\README.txt. No separate
dependency-preparation command is required. Build DelphiProjectHandoff.dproj
with RAD Studio 37 for Win32 and Win64 in
Debug and Release as needed. Run from the matching bin\platform\configuration
folder with WebView2Loader.dll beside the executable and the repository's
Localization, migrations, help, and images and icons folders accessible.
The selected target application is read statically and must not be launched
by DPH's ordinary Open application workflow.

From an elevated RAD Studio command prompt at the source root, use focused
checks for the contract changed. Current scripts include:

  tools\build-wp0.cmd                 storage and baseline form checks
  tools\build-learning-refocus.cmd    current six-view learning route
  tools\build-ui-translation.cmd      35 interface language packs
  tools\build-wp6.cmd                 browser and local preview checks

Run broader analyzer and storage regression suites when changing those
layers. Every invoked script should finish with PASS and exit code 0. Use
a fresh disposable Temp directory for tests that create a .dphdb; never
point a test at an owner's saved project. Keep failure evidence until the
cause is understood and remove only the exact disposable test directory.

For a manual first-session check, follow Run_And_Test.txt. Include a small
external Delphi project, a project with incomplete or unsupported source,
and a saved .dphdb. Verify that the dossier distinguishes source evidence,
partial capture, and static-inspection limits. Reopen the saved project with
its original source available and confirm that DPH verifies it; a changed
manifest or analyzer version should start an incremental scan. Reopening an
unchanged partial capture should reuse its saved findings without another
generation; inspect diagnostics and missing inputs before calling it current
or complete. The phrase Static
inspection only should remain on every capture.

Generated form views should be checked against the source .fmx or .dfm and
must be described as reconstructions. Check that screenshots and diagrams
start at a readable size, remain scrollable, and preserve selection routes.
Review both User and Engineering Guide DOCX/PDF pairs and local HTML help
after editing guide source; the guide build and render scripts are in tools.

Historical practice-example and lesson-authoring tests remain in the
repository for regression work on those modules. They are not the current
first-use route and are not prerequisites for an ordinary DPH launch.
